## 2026-10-15 · T01 — Repository, tooling, Compose, settings

**Produced by AI**
- Repo layout per BLUEPRINT §H1; `backend/pyproject.toml` (uv, ruff, pytest config), `uv.lock`,
  multi-stage `backend/Dockerfile` (runtime + test targets, tiktoken files baked in),
  `compose.yml` (db, redis, api, worker), `compose.test.yml`, `.env.example`, `.gitignore`,
  `.gitattributes` (LF endings so scripts work in Linux containers), `app/core/config.py`.
- Versions looked up on PyPI and Docker Hub on 2026-10-15 and pinned in `pyproject.toml`; full
  resolution in `uv.lock`. Images: `pgvector/pgvector:0.8.7-pg17`, `redis:8.2.10`,
  `python:3.12-slim-trixie`, `ghcr.io/astral-sh/uv:0.12.1`.

**Problems found and fixes**
- `uv lock` on the Windows host failed while installing a managed Python 3.12 ("Missing expected
  target directory"). Fix: lock inside the `ghcr.io/astral-sh/uv:0.12.1-python3.12-trixie-slim`
  container, which is also closer to the runtime.
- `kombu 5.6.2` caps `redis-py` below 6.5, so the latest `redis` (8.1.0) can't be used; pinned
  `redis==6.4.0` (the resolver's choice) explicitly.
- SQLAlchemy 2.1 no longer installs `greenlet` by default; the async engine failed with
  `ImportError`. Fix: depend on `sqlalchemy[asyncio]`.
- api and worker shared one `build:` + `image:` and Compose tried to export the image twice
  ("already exists"). Fix: only `api` builds; `worker` reuses the image (`pull_policy: never`).
- **Found by running the stack:** `/health/ready` reported `key_present: true` with an empty key.
  Docker Compose parses `OPENAI_API_KEY=   # comment` as the literal value `# comment`. With
  `AI_PROVIDER=openai` that comment would have been sent as the API key. Fixes: the comment in
  `.env.example` moved to its own line (content otherwise as specified in MASTER_PROMPT §3), and
  the settings validator treats blank or `#…` values as "no key" (unit test added).

**Verification (actually run)**
- `docker compose up -d --build` → db, redis, api healthy; worker running; `GET /api/v1/health/ready`
  → `{"status":"ready", ... "ai_mode":"fake", "key_present": false}`.
- `docker compose -f compose.test.yml run --rm tests sh -c "ruff format --check . && ruff check . && pytest -q"`
  → all checks passed, 15 passed.

## 2026-10-15 · T03 — Errors, request IDs, JSON logs, health, worker heartbeat

**Produced by AI**
- Error envelope `{"error":{"code","message","details"},"request_id"}` for app errors,
  validation errors (`VALIDATION_ERROR`, 422) and HTTP errors (`NOT_FOUND`, …).
- Pure-ASGI `RequestContextMiddleware`: accepts a safe incoming `X-Request-ID` or generates one,
  echoes it on every response, logs one JSON access line, and converts unhandled exceptions into a
  500 envelope while keeping the header. Pure ASGI so streamed (SSE) responses are not buffered.
- stdlib JSON log formatter with a fixed allow-list of extra fields (IDs, stage, timings, tokens);
  anything else passed as `extra` is not emitted, which keeps document text out of logs.
- `/health` (liveness) and `/health/ready` (DB + pgvector version, both Redis DBs, worker heartbeat
  key with 30 s TTL refreshed every 10 s by a worker thread, AI configuration). `unavailable` (503)
  only when DB or Redis is down; `degraded` (200) when the worker or AI configuration is missing.

**Verification (actually run)**
- Tests: request-ID echo/generation, 404 envelope, ready/degraded/unavailable states (Redis
  pointed at a closed port), `AI_NOT_CONFIGURED` reported, formatter allow-list. All passed
  (part of the 15 above).
- Live stack: worker heartbeat seen by `/health/ready` (`last_heartbeat_age_s: 9`).
